## 1. 研究主线：为什么要做严格留出评价

项目早期使用**随机划分**（7:2:1，seed=42）训练与评价，得到很高的分数。但随后对数据做泄漏审计时发现：

- 随机划分会**把同一场景/同一缺陷的近重复图像分到不同 split**；
- 这类同源近重复会让验证分数被**系统性高估**。

为此项目重建了 **split_v2：按场景/约束组划分的严格留出集合**，保证同源图像不跨 split，
并在此基础上重新训练与评价（detector 记为 `V2-AUG-RERUN1`）。

## 2. 严格留出评价结果

### 2.1 检测（`split_v2` test，n = 1,179）

| 指标 | 值 |
|---|---|
| **mAP50** | **0.1632** |
| **mAP50-95** | **0.0597** |
| 工作点 P（conf 0.075 / IoU 0.45 / max_det 30） | **0.2786** |
| 工作点 R | **0.2111** |
| 工作点 F1 | **0.2402** |

工作点逐类 F1：**peeling 0.1515 / crack 0.2228 / rust 0.3719**。

### 2.2 分割（60 张参考掩码上的 C / D 分支）

| 分支 | binary IoU | P | R | F1 | macro class IoU |
|---|---|---|---|---|---|
| **C**（SAM2 原始） | **0.1133** | 0.4119 | 0.1352 | 0.2036 | 0.1386 |
| **D**（C + 预设后处理） | **0.1124** | 0.4044 | 0.1346 | 0.2020 | 0.1377 |

**读法**：D 与 C 有差异但整体几乎持平（D 略低），说明该预设后处理在此数据上既没救回漏检、
也没明显去掉误检——**按该结果如实报告，不做调参**。

## 3. 主要结论

1. **随机划分下的高分不可信**：泄漏审计表明同源近重复跨 split 是普遍现象。
2. **严格跨场景评价暴露了真正的瓶颈**：mAP50 仅 0.1632，说明模型在**未见场景**上的泛化不足。
3. **瓶颈主要在检测器**：分割分支 C/D 的表现受限于上游检测（漏检直接导致掩码缺失），
   检测器是级联链路的主要瓶颈。

## 4. 必须一起读的边界

- 60 张分割参考掩码是 **human-confirmed reference masks**（预标注为模型产出后经真人确认），
  **不是** independent human ground truth；它是**像素评价的参考集**，不是检测训练数据，也不是官方标注。
- 分割评价只在这 60 张上做（筛选条件为「在 test split 内」，**与模型表现无关**）；
  检测评价在 test 全量 1,179 张上做。两者口径不同，**不可混用**。
- 指标偏低是**接受的结果**，不是需要重跑或调参的信号。

## 5. 与 V3 的关系

V2 的严格评价**没有被 V3 推翻**，反而**被 V3 进一步解释**：
问题具有明显的**数据域依赖性**——V2 在严格跨场景评价中较弱，而在针对某个新来源做受控适配后，
该来源上的留出性能显著提高。详见 [V3_DOMAIN_ADAPTATION_SUMMARY.md](V3_DOMAIN_ADAPTATION_SUMMARY.md)。
